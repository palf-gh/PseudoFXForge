# 制作記録

## 2026-10-19

### 目的

JSONからAfter Effectsの疑似エフェクト用FFXを生成し、ExtendScriptから保存・再利用・適用できるライブラリを作る。配布物は単一の `.jsxinc` とし、実行時に外部コマンドを必要としない。

### 設計方針

- JSON文字列は `eval` を使わず解析する。
- 入力を正規化してから、FFXと識別子を生成する。
- キャッシュの再利用では完全な内容を比較する。
- 保存処理では一時ファイルを検証してから既存ファイルを置き換える。
- AEへの登録に使う一時項目は、失敗した場合も除去する。
- 入力検証、ファイル操作、登録、適用の失敗を区別する。

### 可読性と文書の更新

利用者の指摘に合わせ、本体の変数名を明瞭にし、値の意味を名前付き定数で示した。処理の区切りには空行を入れ、役割を示す最小限の日本語コメントを追加した。

その後の指摘に合わせ、コメントを登録・判定などの処理の役割を示す短いラベルへ絞った。

日本語版と英国英語版のREADMEを単一ファイルへ統合し、冒頭の言語リンクから各節を参照できるようにした。

- JSON Schema Draft 2020-12のスキーマ自己検証：成功。
- `examples/all-controls.json` とスキーマの照合：成功。
- 型に適合しない属性をスキーマが拒否することを確認。
- 自動テスト29項目：成功。AEの代替オブジェクトを使うテストを含むため、実機での互換性の確認とは区別する。
- 初期のAcorn 8.15.0によるES3構文検査は成功したが、予約語を識別子として許す設定だったため、ExtendScript互換性の確認として不十分だった。
- 日本語READMEと制作記録について、実装ソースを資料として日本語推敲用の検査を実行。検査の実行と文章の意味・正確さの確認は別に扱う。

手動検証用の `tests/ae-validation.jsx` を用意し、実行を依頼した。レポートの保存先は `Folder.temp` 配下の `PseudoFXForge-validation.txt`。Windowsでは `%TEMP%/PseudoFXForge-validation.txt` に相当する。実機試験で構文エラーと登録失敗を調査し、診断用の最小構成では登録に成功した。配布ライブラリの全コントロール型を含む最終試験は未完了。macOSでの動作は未検証。

### 実機試験で判明した構文エラー

利用者からAEの `Eval Error #9` が報告された。`byte(codePoint)` の `byte` が将来の予約語に当たり、スクリプトの読み込み時に拒否された。関数名を `encodeByte` へ変更し、`default` のプロパティ表記も文字列キー・角括弧へ変更した。READMEのコード例も `'default'` と明示した。

関数名とプロパティ表記の修正を終え、予約語を拒否するAcornの `allowReserved: 'never'` を使った恒久的なES3構文検査を追加した。開発用依存関係は `npm ci` で導入する。`npm test` でNodeの29テストと厳格なES3構文検査が成功し、`npm run check:es3` で構文検査だけを実行できる。

Dropdownの項目数は、格納先が符号付きの `A_short` であることを踏まえ、上限を32767へ変更した。実装では `FORMAT.MAX_DROPDOWN_ITEMS` に値をまとめ、READMEとスキーマも同じ上限へ更新した。

### 登録失敗の診断と識別子の修正

AEの診断試験では対照例の登録が成功した。短い実際のmatchNameを持つ5例もすべて登録に成功し、Sliderの初期値25を確認した。一方、32文字の実際のmatchNameを持つ5例はすべて登録に失敗した。後者は長さの影響を調べるための診断例であり、全機能の受け入れ試験とは区別する。

利用者からの警告画像には、次元数が期待値1に対して8193と解釈される現象があった。SCALARとCOLOURのシグネチャーに転記誤りがあり、`0xbd992001`・`0xbd992004` を `0xbd990001`・`0xbd990004` へ修正した。値は十進表記ではなく16進表記で保持する。ソースレイヤーIDはコントロール数に依存させず、`REFERENCE_LAYER_ID` の定数1へ変更した。

matchNameに付ける識別子は、64ビットの指紋をすべて保持したまま、16桁の16進表記から13文字のBase32表記へ変更した。入力のmatchNameは17文字まで、区切りは `_` 1文字とし、実際のmatchNameを31文字以内に収める。`normalise.fingerprint` は16桁の16進表記を維持する。

これらの修正後、28件の自動テストと5ファイルの厳格なES3構文検査が成功した。

### 入れ子の三項演算子とエンコード形式の修正

次の実機報告は成功2・失敗1で、AEは「ファイルのデータが見つかりません」と報告した。AEで生成したルートの `tdb4` フラグが `0x10004` となり、`srcNode` の想定値 `0x10000` と異なっていた。入れ子の三項演算子がAEで異なる結合評価になることが原因と判明し、本体の該当4箇所を明示的な分岐または補助関数へ置き換えた。

互換性検査では入れ子の三項演算子を禁止し、再発を検出する。`FORMAT.ENCODING_VERSION` は2へ更新し、修正前に部分登録された古い定義と同じmatchNameを再利用しないようにした。

手動検証スクリプトには、AEで実際に書き出したバイナリーの次元数・ルートフラグ・CDAT長を確認する処理を追加した。異常があれば `applyPreset` より前に失敗として報告する。

修正後の自動テスト29件と厳格な構文・互換性検査は成功した。今回の修正後のAE実機結果は未確認で、再試験を依頼する段階にある。配布ライブラリの全コントロール型を含む最終試験が完了したとは記録しない。
